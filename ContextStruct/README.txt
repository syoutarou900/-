ContextStruct v2 ― 非構造化資料（PDF・画像）の「文脈特化型・即時構造化アシスタント」
========================================================================

■ これは何をするアプリか
FAXのPDF、スキャンした納品書、レイアウトがバラバラなWEBカタログなどから、
自社の業務ルール（プロファイル）に沿って必要な数値・項目を拾い、
登録フォーマット（Excelの列順）に整えて取り出す Windows デスクトップアプリです。
※ Mac対応リトロフィット（2026-11-14）で、Macでもソースから起動し、利用者の
   Mac上で .app 化できる形になりました。Macでの手順と制限は末尾の
   「■ Macでの利用」章に正直にまとめています。Windowsの動作は従来と同一です。
「卸値」と「売価」のように、見出しで区別される金額も別々の項目として扱えます。
v2 では、精度の最大化（複数エンジンの合意＋検証）、完全自動化（監視フォルダー）、
大規模モデル級の品質への接近（7Bモデル＋自己整合）、修正からの学習、
GPU対応、基幹システム連携（4方式＋設定アシスト）を追加しました。

■ 使いかた（初回）
1. ZIPをすべて展開（解凍）してください。展開せずに中身を直接実行しないでください。
2. 展開したフォルダー内の Start-ContextStruct.bat をダブルクリックします。
3. 初回だけ、必要なライブラリ（PySide6・OpenCVなど、数百MB規模）を自動で入れます。
   2回目以降は確認だけですぐ起動します。
4. 起動中は黒い画面（コマンド画面）を閉じないでください。閉じるとアプリも終了します。
5. PDF／画像／テキストを大きな枠へドラッグ＆ドロップ（クリックでも選択可）し、
   プロファイルを選び、「構造化する（抽出）」を押します。
6. 確認モードで色を確認します（緑＝信頼度80以上／黄＝50〜79／赤＝50未満・未検出）。
   セルはその場で直せます（直すと信頼度100の手動確定になります）。
7. 「確定してコピー」でExcelへそのまま貼り付けできます。Excel／CSV出力、JSONコピーも可能です。
画面キャプチャボタン（ホットキー Ctrl+Shift+S、設定で変更可）でも取り込めます。

■ 精度を上げる仕組み（v2-A/D: アンサンブル＋検証）
・画像の前処理（preprocess.py）: OpenCVで傾き補正・ノイズ除去・コントラスト強調
  （CLAHE）・適応二値化・2倍拡大を行い、「原画／強調／二値化」のバリエーションを
  OCR・VLMへ渡します。汚れたFAXや手書き混じりの読み取りを底上げします。
・複数エンジンの合意: PDFテキスト層、Tesseract OCR（原画＋前処理バリエーションが
  それぞれ投票）、内蔵VLM、（任意で）easyocr/paddleocr、外部API VLM が同じ文書を読み、
  項目ごとに投票します。2つ以上のエンジンが一致した値は信頼度97〜99へ引き上げ、
  意見が割れた値は信頼度に上限を付けて検証対象にします。
・検証パス: (a) 検算 ― 数量×単価≒合計、明細の合計、消費税8%/10%のパターンを照合し、
  合わない項目の信頼度を下げます。(b) 項目別の再読 ― 意見が割れた／検算に失敗した
  項目だけ、VLMへ「その項目だけ」の質問で再読します。(c) マスター照合 ― 設定で
  指定した商品・取引先マスターCSV（code,name 列、または先頭2列）にあいまい照合し、
  一致すればマスターの表記にそろえて信頼度を上げます。
※ それでも「精度100%の保証」はできません。人間でも判読できない汚れ・崩れた手書きは
   読めません。読めない項目は推測で埋めず空欄＋低信頼度で出す設計です。
   完全自動モード（下記）以外では、必ず確認モードで人の目を通してください。

■ 完全自動化（v2-B: 任意機能）
・監視フォルダー: 設定で監視フォルダー・出力先・処理済みフォルダー・要確認フォルダー・
  自動確定のしきい値（既定90）を指定すると、新しく入ったファイルを自動処理します。
  全項目の信頼度がしきい値以上で検算も通れば、出力先（Excel/CSV、または連携先）へ
  自動で追加し、監査ログ（audit_log.jsonl）に「いつ・どのファイル・どの値・
  信頼度・どのエンジンが合意したか」を記録して、元ファイルを処理済みフォルダーへ
  移します。条件を満たさないファイルは要確認フォルダーへ移り、アプリ内の
  要確認キューからクリックで通常の確認モードで開けます。
・バッチ自動: メイン画面の「完全自動モード」をONにして複数ファイルを落とすと、
  1つずつ自動処理し、結果（自動確定／要確認の件数）を表示します。
・このモードは「人の確認なしに登録する」モードです。使うかどうかは利用者の
  判断であり、有効化した事実と全処理は監査ログに残ります。

■ 内蔵ローカルVLM（APIキー不要・完全オフライン動作）
・推論ランタイム: llama.cpp 公式 Windows x64 CPU ビルド b10936 の
  llama-mtmd-cli.exe と必要DLLを、このアプリの vlm_runtime フォルダーに同梱済みです。
・モデルは2種類から選べます（設定画面）:
  - 3B（軽量）: Qwen2.5-VL-3B-Instruct GGUF
      本体 Qwen2.5-VL-3B-Instruct-Q4_K_M.gguf = 1,929,901,056 bytes
      mmproj mmproj-Qwen2.5-VL-3B-Instruct-Q8_0.gguf = 844,757,728 bytes
      合計 2,774,658,784 bytes（約2.8GB）
  - 7B（高精度）: Qwen2.5-VL-7B-Instruct GGUF
      本体 Qwen2.5-VL-7B-Instruct-Q4_K_M.gguf = 4,683,072,032 bytes
      mmproj mmproj-Qwen2.5-VL-7B-Instruct-Q8_0.gguf = 853,119,712 bytes
      合計 5,536,191,744 bytes（約5.5GB）
  ファイル名とサイズは Hugging Face 公式APIで実在を確認済みです。
・モデル本体は大きいためZIPには入れていません。初回のVLM利用時、または
  ダウンロードボタンから、進捗バー付きで %APPDATA%\ContextStruct\models へ
  自動ダウンロードします。ダウンロード後は完全オフラインで動作し、APIキーは不要です。
・自己整合（v2-C）: VLMは同じ画像を「言い回しの違う2つのプロンプト」で2回読み、
  一致した項目の信頼度を上げ、割れた項目は検証パスの再読に回します。
・外部API（OpenAI互換エンドポイント）を設定した場合は「最大精度・クラウド」として
  アンサンブルの1票になります（既定はOFF。使う場合のみAPIキーが必要です）。
・画像理解とOCRの違い: OCR＝文字の読み取りのみ（補助）。VLM＝画像そのものを見て、
  表の行列構造・見出しと数値の位置関係・罫線の欄を読み、項目へ対応付けます。
  画像ファイルはそのまま、スキャンPDFはページを高解像度（最低200DPI）で
  画像化してからVLMへ渡します。手書きは「読める範囲で」解釈します。

■ GPU対応（v2-H: 任意）
・グラフィックボード搭載PCでは、GPU版ランタイムでVLMを高速化できます。
  設定画面から llama.cpp 公式の GPU版を取得できます:
  Vulkan版（llama-b10936-bin-win-vulkan-x64.zip、31,673,236 bytes）と
  CUDA版（llama-b10936-bin-win-cuda-12.4-x64.zip、254,065,100 bytes ＋
  cudart-llama-bin-win-cuda-12.4-x64.zip、391,443,627 bytes）。
・GPU版がある場合はそちらを優先して起動し、GPUへレイヤーをオフロード（-ngl）します。
  起動に失敗した場合は自動でCPU版へ戻ります。
・内蔵グラフィックスのみのPCではCPU動作になります。設定画面に現在の実行モード
  （CPU / GPU(Vulkan) / GPU(CUDA)）と検出結果が表示されます。
  ※「GPU無し」とはグラフィックボード（GPU）が無いという意味で、
    内蔵グラフィックスのみのPCではCPUで処理します。

■ 学習（v2-E: モデルの再学習ではありません）
・確定した修正は learning.jsonl に記録されます。
・キーワード学習: 修正した値の近くにあった未知の見出し語を、その項目の
  キーワードとしてプロファイルへ自動追加します（プロファイル編集で確認できます）。
・VLMへの例示: 同じプロファイルの直近の修正5件を、VLMのプロンプトへ例として渡します。
・取引先ごとの記憶: 取引先ごとに最後に使ったプロファイルを覚え、次回自動で選びます。
・正直な位置づけ: これはモデルの再学習（ファインチューニング）ではなく、
  辞書と文脈（プロンプト）による学習です。重い処理を担うのはネイティブの
  C/C++エンジン（llama.cpp・Tesseract・OpenCV）で、Pythonがそれらを取りまとめています。

■ 基幹システム連携（v2-I: 任意の上級機能）
連携は任意の上級機能です。未設定でも本体の流れ（ドロップ→構造化→確認→
コピー／Excel出力）は完全に使えます。対象は確認モードで確定した行
（完全自動モードでは自動確定した行）です。
・方式1 RPA画面自動入力: 対象画面の先頭欄にフォーカスして実行すると、
  値を「入力→Tab→入力…」で自動入力します。開始前3秒カウントダウン、
  Escキーで即時中止、項目ごとの間隔は設定可能です。最後の「登録」クリックは
  任意機能で、利用者が実物の登録ボタンをクリックして座標を記録した場合に
  限り、その記録済み座標だけをクリックします（記録なしに推測でクリックしません）。
・方式2 Webフォーム連携: 項目→CSSセレクタの対応表から、ブラウザで実行すると
  フォームへ値を流し込むブックマークレットを生成します。selenium が入っている
  環境では、URLを開いて直接入力する経路も使えます（ドライバは同梱しません）。
・方式3 取り込みファイル連携: 形式（CSV/TSV/Excel）・文字コード（UTF-8/Shift-JIS）・
  改行（CRLF/LF）・ヘッダー有無・日付書式・列の並び・日付入りのファイル名を
  指定して書き出します。完全自動モードの出力先としても選べます。
・方式4 データベース直接書き込み: 既定はドライラン（実行予定のINSERT文を
  プレビューするだけで書きません）。連携プロファイルで「DB直接書き込みを
  有効化」を明示ONにした場合だけ、トランザクションで書き込み、監査ログにも
  記録します。sqlite は標準機能で動作し、ODBCは pyodbc がある場合のみ使えます。
・完全自動モードの出力先に選べるのは方式3と方式4（有効化済み）だけです。
  方式1・2は画面操作が前提のため手動実行のみです。

■ 連携の設定アシスト（手入力を減らす仕組み）
・Webフォーム「クリックで欄を覚える」: 学習用ブックマークレットを対象フォームで
  実行すると、項目名の順に案内が出るので、対応する入力欄をクリックしていくだけで
  対応表（CSSセレクタ）のJSONが得られます。アプリ側の「対応表JSONを取り込む」で
  読み込めます（セレクタは id優先→name→位置パスの順で自動生成されます）。
・取り込み仕様の自動推定: 取引先のサンプル取り込みファイル（CSV/TSV）を
  連携ダイアログへドロップするか「サンプルファイルから仕様を推定」を使うと、
  文字コード（UTF-8/Shift-JIS）・区切り・ヘッダー有無・列順を推定して
  方式3の下書きを自動作成します。あとは確認と微調整だけです。
・連携プロファイルの書き出し／読み込み: 連携プロファイルをJSONで出し入れできます。
  会社の中で詳しい人が1回設定してプロファイルを配れば、全員が読み込んで
  そのまま使えます。個人サイト等で「プロファイル例」を配る運用も可能です。
・DB接続アシスタント: 接続文字列を手で書く代わりに、種類（SQLiteはファイル選択／
  ODBC）・サーバー名・DB名をフォームに入れ、「接続テスト」で接続を確認してから、
  テーブルは一覧から、列の対応はテーブルの列一覧からドロップダウンで選べます。
・運用上の注意: DB接続情報は各会社の管理者のものを使ってください。
  アプリや配布サイトに、他社の接続情報を同梱することは決してありません。
  4方式とも仕組みはアプリに内蔵されていますが、実際に使うには連携先ごとの
  情報（セレクタ・取り込み仕様・DB接続情報とその会社の許可）が利用者側で必要です。
  接続先を推測する機能はありません。

■ 配布者向けフルパッケージ（サイト配布用）
モデルまで含めた完全版を自分のサイトで配りたい場合は:
1. Download-Models.bat を実行（または python download_models.py）すると、
   3Bと7Bの両モデル（合計 約8.3GB）をダウンロードし、サイズを検証します。
2. ダウンロード先（%APPDATA%\ContextStruct\models）の中身を、展開した
   ContextStruct フォルダー直下の models フォルダーへコピーしてください。
   アプリは起動時にアプリデータ側→同梱 models フォルダーの順で探すため、
   models を含むZIPを配れば、利用者はダウンロードなしで使えます。
3. フォルダー全体を再圧縮して配布してください（約8.4GB規模になります）。

■ プロファイル（文脈）の編集
プロファイル編集画面で、表示名・出力列名・キーワード（カンマ区切り）・種類
（テキスト／数値／日付／金額）・必須を、追加・削除・並べ替えできます。
保存先は %APPDATA%\ContextStruct で、JSONの書き出し／読み込みもできます。
同梱プリセット: 納品書／請求書／WEBカタログ商品／汎用。
納品書とWEBカタログには「卸値」と「売価」が別項目で入っています。

■ 表示言語（13言語）
日本語／English／Español／简体中文／Français／Deutsch／Português／Русский／
Italiano／Türkçe／العربية（RTL表示）／Bahasa Indonesia／한국어
ヘッダー右上のセレクタで切り替え、設定は保存されます。v2の新機能
（完全自動化・連携・GPU・学習・設定アシスト）の文字列も全13言語に収録しています。

■ 正直な制限（必ずお読みください）
・精度100%の保証はありません（上記参照）。完全自動モードは利用者が選ぶ
  無人登録であり、全件が監査ログに残る前提の機能です。
・GPUのないCPUパソコンでは、VLMは1ページに数十秒〜数分かかる場合があります
  （7Bはさらに時間がかかります）。「即時」に終わるのはルール抽出の方です。
・OCRを使うには、Windows側に Tesseract 本体のインストールが必要です
  （公式配布: https://github.com/UB-Mannheim/tesseract/wiki など。
   日本語データ jpn を含め、PATHを通してください）。未導入でもアプリは止まらず、
   抽出テキスト欄へ貼り付け・手入力してルール抽出できます。
  Macでは Homebrew で導入します（brew install tesseract tesseract-lang。
  詳細は末尾の「■ Macでの利用」章）。
  easyocr / paddleocr は任意の追加投票エンジンです。インストールされている
  場合のみ自動で使われます（重いため必須にはしていません）。
・実Windows機での起動、および実Windows機でのVLM/GPU実行は未検証です
  （制作環境ではオフスクリーン描画と単体テストで確認しています）。
・初回起動時はライブラリ（PySide6・OpenCV等、数百MB）の自動導入が入ります。

■ サイズの目安
・このZIP（v2）: 約11.8MB
・展開後: 約32.9MB
・初回起動で入るライブラリ: 数百MB（PySide6・OpenCVほか）
・VLMモデル（任意・初回のみ別途）: 3B 合計 約2.8GB ／ 7B 合計 約5.5GB
・GPUランタイム（任意）: Vulkan 約32MB ／ CUDA 合計 約645MB

■ Macでの利用（Mac対応リトロフィットで追加）
対応環境: macOS 11（Big Sur）以降。Apple Silicon（Mシリーズ）と Intel の
両方のMacに対応します（下記 .app 化の際に、まず両チップ兼用の universal2
での生成を試み、できない場合はそのMacのチップ専用版に自動で切り替えます）。

【手順A: ソースから起動する】
1. ZIPをすべて展開（解凍）してください。
2. 展開したフォルダー内の Start-ContextStruct.command をダブルクリック
   します。未署名のため初回だけ止められる場合があります。その場合は
   右クリック→「開く」を選んでください（Gatekeeper の仕様です）。
3. 初回だけ、専用の実行環境（.venv）の作成と必要ライブラリ
   （PySide6・OpenCVなど、数百MB規模）の自動導入が入ります。
   2回目以降はすぐ起動します。
4. Python 3 が無いMacでは、入手方法（python.org のインストーラ／
   Homebrew／xcode-select --install）が画面に表示されて終了します。
   入れたあと、もう一度ダブルクリックしてください。

【手順B: .app 化する（通常はこちらがおすすめ）】
1. 展開したフォルダー内の MakeApp-Mac.command をダブルクリックします
   （初回は右クリック→「開く」）。
2. 生成が終わると dist フォルダーに ContextStruct.app ができます。
   あとはその .app をダブルクリックして使えます（.app 自体も未署名の
   ため、初回起動時は右クリック→「開く」が必要です）。

【Macでのデータ保存先】
設定・プロファイル・学習記録・監査ログ・VLMモデルの保存先は、Mac標準の
 ~/Library/Application Support/ContextStruct です（Windows版の
 %APPDATA%\ContextStruct に相当。ファイル形式は同じです）。

【MacでのOCR】
Homebrew で導入します: brew install tesseract tesseract-lang
Apple Silicon の /opt/homebrew/bin と Intel の /usr/local/bin の両方を
アプリが自動で探すので、Finderから起動した場合でも見つけられます。
未導入でもアプリは止まらず、画面に導入方法の案内が出ます（その場合、
スキャンPDF・画像のOCRだけが使えず、貼り付け・手入力とテキスト層の
あるPDFのルール抽出は通常どおり使えます）。

【Macでの制限（正直な明記）】
・ローカルVLM（内蔵Qwen2.5-VL）: 同梱の推論ランタイム（llama.cpp）は
  Windowsビルドのため、Macではそのままでは動作しません。モデル本体の
  ダウンロード自体はMacでもできますが、推論には macOS版 llama.cpp の
  llama-mtmd-cli（拡張子なしの実行ファイル）を vlm_runtime フォルダー
  へ手動で配置する必要があります（上級者向け。配置すれば自動で検出
  されます）。設定画面のGPUランタイム取得（Vulkan／CUDA）もWindows
  専用の配布物のため、Macでは取得できません。なお、外部APIのVLM
  （OpenAI互換エンドポイント）を設定した場合は、MacでもVLMの票を
  アンサンブルに使えます。ルール抽出・OCR・検算・マスター照合などの
  VLM以外の仕組みはMacでもすべて動作します。
・キャプチャ用ホットキー: 他のアプリを使っている最中でも効く
  グローバルホットキーは Windows専用の仕組みのため、Macでは使えません。
  Macでは ContextStruct のウィンドウが前面にある間だけ、設定した
  ショートカット（既定 Ctrl+Shift+S）が効きます。「画面をキャプチャ」
  ボタンは通常どおり使えます。
・画面キャプチャ: macOSの仕様で「画面収録」の許可を求められる場合が
  あります（システム設定→プライバシーとセキュリティ→画面収録）。
  許可しない場合は、ファイルをドラッグ＆ドロップ／選択して取り込んで
  ください。
・基幹システム連携の方式1（RPA画面自動入力）は Windows専用です。
  Macでは利用不可として扱われます。方式2（ブックマークレット／
  selenium）・方式3（取り込みファイル）・方式4（DB直接書き込み）は
  Macでも動作します。
・監視フォルダー（完全自動化）はMacでも動作します（アプリ起動中に
  定期確認する方式のため、アプリを閉じている間は処理されません。
  これはWindows版も同じです）。
